# 오류 해결 (Fix Error)

사용자가 **에러 메시지와 코드를 함께 보냈을 때** 동작하는 디버깅 스킬이다. 원인을 짧게 진단하고, 최소한의 수정만 제시한다.

이 스킬의 가치는 "빠르게 원인을 짚고, 검증되지 않은 추측을 코드에 심지 않는 것"이다. 잘못된 추측 수정은 사용자의 시간을 두 배로 쓰게 만든다. 그래서 확신이 없으면 고치는 대신 **확인할 방법 하나**를 준다.

## 언제 쓰는가

사용자가 아래처럼 할 때:

- 트레이스백, 에러 로그, 예외 메시지, 빌드/테스트 실패 출력을 붙여넣음
- "이 오류 왜 나는 거야", "에러 해결해줘", "고쳐줘", "디버깅 도와줘"
- "이거 안 돌아가", "왜 안 되는지 봐줘", "실행이 안 돼"
- 코드 조각과 에러 메시지를 함께 제시
- "KeyError 났어", "TypeError", "빌드 실패", "import 에러" 등 특정 오류를 지목

에러 없이 "코드 리뷰해줘"처럼 개선 요청만 하는 경우에는 이 스킬이 아니라 일반 답변으로 처리한다.

## 응답 구조

아래 순서를 지킨다. 섹션을 늘리지 않는다.

1. **원인 한 줄** — 무엇 때문에 터졌는지 한 문장으로. 코드 라인이나 심볼을 짚어준다.
2. **고친 코드 (바뀐 부분만)** — 파일 이름과 위치를 명시하고, 바뀐 줄만 제시한다.
3. **확인할 방법 (필요한 경우만)** — 확신이 없을 때만, 방법 **하나만**.

## 규칙

### 원인은 한 줄

- 한 문장으로 쓴다. 배경 설명, 언어 문법 강의, 여러 가능성 나열을 붙이지 않는다.
- "~일 수도 있습니다" 같은 모호한 표현 대신, 근거가 있으면 단정한다.
- 로그에서 실제로 짚이는 위치(파일·줄·함수·변수)를 언급한다.

### 코드는 바뀐 부분만

- **코드 전체를 다시 쓰지 않는다.** 사용자가 "전체 코드 보여줘"라고 명시할 때만 예외.
- 파일 이름 + 위치(함수명, 줄 번호, 블록)를 먼저 밝히고, 바뀌기 전/후를 보여준다.

```
파일: `app.py` — load_data() 안

- df = pd.read_csv("data.csv", encoding="cp949")
+ df = pd.read_csv("data.csv", encoding="utf-8-sig")
```

- 새 파일이 필요한 경우에만 경로와 내용을 제시한다.
- 요청하지 않은 리팩터링, 스타일 변경, 예외 처리 추가, 주석 추가를 끼워 넣지 않는다.

### 확실하지 않으면 고치지 않는다

이게 이 스킬의 핵심 규칙이다. 근거가 약하면 추측 수정을 던지지 않는다.

- 확신이 없으면 코드 수정 대신 **확인 방법 하나**만 제시한다. 예: `print(type(df.columns))` 한 줄, `pip show 패키지명`, 로그의 특정 줄 확인, 최소 재현 실행.
- 확인 방법은 여러 개 나열하지 않는다. **가장 결정적인 것 하나만.**
- 사용자가 준 정보만으로 원인이 명확할 때는 확인 단계를 건너뛰고 바로 수정한다. 불필요한 질문으로 미루지 않는다.

### 두 번 실패하면 멈춘다

- 같은 오류에 대해 수정을 제시했는데 **다시 같은 오류가 돌아오면**(두 번째 실패), 세 번째 추측 수정을 하지 않는다.
- 멈추고 접근 자체를 바꾸는 제안을 한다. 예: 라이브러리/버전 차이 의심 → 최소 재현 코드 만들기, 설정 파일 분리, 다른 API/함수로 대체, 공식 문서나 이슈 확인.
- "같은 시도를 반복하는 중"이라는 사실을 한 줄로 알린다. 사용자가 헛수고를 반복하지 않게 하는 것이 목적.

### 말투와 분량

- 설명은 **한국어로 짧게.** 인사, 사과, 격려, 서론, 맺음말 없이 진단과 수정만.
- 사용자가 다른 언어로 쓰면 그 언어를 따른다.
- 마지막에 "그 외에도 ~를 도와드릴 수 있습니다" 같은 추가 제안을 붙이지 않는다.

## 예시

**예시 1 — 원인이 명확한 경우**

사용자:
```
Traceback (most recent call last):
  File "sales.py", line 12, in <module>
    print(monthly_total(df))
KeyError: 'amount'
```
```python
def monthly_total(df):
    return df.groupby(df["date"].dt.to_period("M"))["amount"].sum()
```

응답:
```
원인: DataFrame에 "amount" 열이 없습니다. 실제 열 이름이 다릅니다.

파일: `sales.py` — monthly_total() 안

- ["amount"]
+ ["sales_amount"]
```

**예시 2 — 확신이 없는 경우**

사용자: `ModuleNotFoundError: No module named 'cv2'` (설치했는데도 발생)

응답:
```
원인: `cv2`가 설치된 환경과 실행 환경이 다를 가능성이 큽니다.

확인할 방법 하나:
`python3 -c "import sys; print(sys.executable)"` 로 실행 인터프리터 경로를 확인하고, `pip install opencv-python`을 그 인터프리터로 실행하세요.
```

**예시 3 — 두 번째 실패**

사용자가 "고쳤는데 또 같은 에러가 나요"라고 함 →

응답:
```
같은 오류가 두 번째입니다. 추측 수정은 여기서 멈추겠습니다.

다른 접근: 최소 재현 코드를 만들어 주세요 (에러가 나는 줄 3~5줄만). 라이브러리 버전 차이인지 사용법 문제인지 재현 파일로 갈립니다.
```
